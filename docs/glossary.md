# قاموس المصطلحات: كلمة واحدة لكل شي

نستخدم هذي الكلمات في الداشبورد وتعليق الـ PR والعرض والشروحات. لا نبدّلها بمرادفاتها، لأن المرادف يوهم القارئ إن هذا شي ثاني.

| المفهوم | نكتب | لا نكتب |
|---|---|---|
| نتيجة واحدة من الأدوات | **ملاحظة** (و«ثغرة» فقط لنوع الثغرات الأمنية، مثل «ثغرة في مكتبة requests») | مشكلة، نتيجة |
| الخطورة | **حرجة، عالية، متوسطة، منخفضة** (حسب تصنيف الأداة) | مرتفعة، خطيرة |
| ما يمنع الدمج | **مانعة** / **تمنع الدمج** | مرتفعة الخطورة |
| حالة الملاحظة | **مفتوحة**، **مغلقة بإثبات**، **مستثناة** | قيد التنفيذ، تحتاج معالجة، مُصلحة، إغلاق مثبت، إغلاقات مثبتة، انقفلت |
| الإغلاق في الخط الزمني | **أُغلقت** | انقفلت |
| الوحدة اللي نفحصها | **بناء** («حالة البناء») | إصدار (إلا في «دليل الإصدار»)، «حالة الإصدار» |
| طلب الدمج | **طلب الدمج** (وبالتنكير «طلب دمج») | Pull Request بالعربي |
| مراحل الفحص | **فحص الجودة**، **فحص الأمن** | الفحص الأمني، فحص الـ QA |
| الأشخاص | **المطوّر**، **مراجع الجودة**، **مراجع الأمن**، **مسؤول الشركة** | المطور، مسؤول الأمن، السايبر، مراجع الأمن السيبراني |
| القرار الإيجابي | **موافقة** («الموافقة على البناء»، «تمت الموافقة») | اعتماد، معتمد، «اعتماد البناء»، «تسجيل الموافقة» |
| القرار السلبي على بناء | **إرجاع** («أرجع البناء للمطوّر») | رفض، ترجيع |
| شرح الوكيل | **المشكلة، ليش خطرة، اتجاه الإصلاح** | ليش خطيرة |

**ملاحظات:**
- «رفض الطلب» في صفحة إدارة الحسابات يبقى «رفض»: هذا طلب حساب مو بناء.
- الفرق بين «ملاحظة» و«ثغرة»: الملاحظة أي نتيجة، والثغرة نوع منها.
- يمنع الاختبار `tests/test_glossary.py` رجوع الكلمات الممنوعة في الداشبورد وتعليق الـ PR.
