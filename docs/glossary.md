# قاموس المصطلحات: كلمة واحدة لكل شي

نستخدم هذي الكلمات في الداشبورد وتعليق الـ PR والعرض والشروحات. لا نبدّلها بمرادفاتها، لأن المرادف يوهم القارئ إن هذا شي ثاني.

| المفهوم | نكتب | لا نكتب |
|---|---|---|
| نتيجة واحدة من الأدوات (في الموقع) | **ثغرة** إذا كانت من الأمن السيبراني، و**مشكلة** إذا كانت من الجودة (وبالجمع «ثغرات» و«مشكلات»). حيث يجتمع النوعان: «مشكلات وثغرات» | ملاحظة، نتيجة |
| الخطورة | **حرجة، عالية، متوسطة، منخفضة** (حسب تصنيف الأداة) | مرتفعة، خطيرة |
| ما يمنع الدمج | **عالية الخطورة** / **تمنع الدمج** | مرتفعة الخطورة |
| حالة الثغرة أو المشكلة | **مفتوحة** أو **قيد التنفيذ**، **أُغلقت**، **مستثناة** | تحتاج معالجة، مُصلحة، إغلاق مثبت، إغلاقات مثبتة |
| الإغلاق في الخط الزمني | **أُغلقت** | انقفلت |
| الطلب اللي نفحصه | **الطلب** («حالة الطلب»، «أرجع الطلب») | إصدار (إلا في «دليل الإصدار»)، «حالة الإصدار» |
| طلب الدمج | **طلب الدمج** (وبالتنكير «طلب دمج») | Pull Request بالعربي |
| مراحل الفحص | **فحص الجودة**، **الفحص الأمني** | فحص الـ QA |
| الأشخاص | **المطوّر**، **مراجع الجودة**، **مراجع الأمن السيبراني**، **مسؤول الشركة** | المطور، مسؤول الأمن، السايبر |
| القرار الإيجابي | **موافقة** («تمت الموافقة») | اعتماد، معتمد، «اعتماد البناء»، «تسجيل الموافقة» |
| القرار السلبي على طلب | **إرجاع** («أرجع الطلب للمطوّر») | رفض، ترجيع |
| شرح الوكيل | **المشكلة، ليش خطرة، اتجاه الإصلاح** | ليش خطيرة |

**ملاحظات:**
- «رفض الطلب» في صفحة إدارة الحسابات يبقى «رفض»: هذا طلب حساب.
- قررت سما (12 نوفمبر): في الموقع نكتب «ثغرة» للأمن السيبراني و«مشكلة» للجودة بدل «ملاحظة». تعليق الـ PR والشروحات من الواجهة الخلفية لسا تقول «ملاحظة».
- اسم المنتج بالعربي في الموقع يُكتب «يَقِـــظ» (بالتشكيل والمدّ).
- يمنع الاختبار `tests/test_glossary.py` رجوع الكلمات الممنوعة في الداشبورد وتعليق الـ PR.

- بالإنجليزي: Open / In progress، Closed، Approve، Return request، Assigned requests، Quality check.
- قررت سما (10 نوفمبر): نكتب «الطلب» مو «البناء»، و«قيد التنفيذ» و«الفحص الأمني» و«مراجع الأمن السيبراني» تبقى.
