# يقظ | لوحة الأدوار الأربعة

## التشغيل
يعمل الخادم على الجهاز المحلي فقط. من مجلد المشروع استخدم Python 3.11 أو أحدث:

```powershell
python -m pip install -r requirements.txt
python server.py
```

افتح http://127.0.0.1:8765/ ثم سجّل الدخول أو أنشئ حسابًا. اختر حساب العرض واستخدم كلمة المرور YaqidhDemo-2026. الحسابات: developer وqa وsecurity وcompany-admin. تسجيل الخروج يتيح تجربة الحساب التالي. يعيد إيقاف الخادم بيانات القرارات إلى حالة العرض الأولية.

## ما رُبط فعليًا
- مجلد backend نسخة من ملفات المشروع المرفقة. الخادم يستخدم نموذج Evidence وEvidenceStore، ويقرأ config/policy.yaml بمحرك القواعد الأصلي ويستدعي Verifier لمقارنة بيانات العرض.
- نتيجة المرحلة PASS أو FAIL تأتي من محرك القواعد. خطورة الملاحظة HIGH أو LOW تأتي من Finding.severity. حالة الملاحظة ونتيجة Closure وقرار الإنسان تظهر كحقول منفصلة.
- فلتر الأداة يأتي من Finding.tool وسجل التشغيل التجريبي للمرحلة المعروضة. Semgrep وTrivy أداتان موجودتان في الكود المرفق. Playwright في العرض يمثل سجلًا تجريبيًا للمرحلة المخططة. الواجهة لا تستدعي الأدوات أو الوكيل أو GitHub.
- تفويض الجلسة والدور ونطاق المشروع وتصدير الأدلة والقرار مطبّق في الخادم المحلي. يحدد الخادم الحساب من Cookie، ويرفض الوصول خارج النطاق، ويمنع اعتماد نتيجة FAIL أو نتيجة غير متاحة أو إرسال قرار لمرحلة مختلفة أو SHA قديم. مسؤول الشركة يغيّر دور حساب المراجع أو حالته أو إسناده للمشروع، ويسجّل الخادم التغيير ويلغي جلسة الحساب المتأثر.
- الموافقات المحفوظة تجريبية ولا تحرّك GitHub. نموذج الهوية والمصادقة هنا للمعاينة المحلية؛ يلزم مزود هوية وتخزين دائم ومراجعة تشغيلية عند النشر.

## مصدر المؤشرات
- الملاحظات المفتوحة: Finding.status == open للمرحلة المعروضة.
- الإغلاقات المثبتة: Closure.result == closed. تفاصيل قبل/بعد تُربط ببصمة الملاحظة ومخرجات Verifier.
- تشغيلات الأدوات المكتملة: العدد من سجلات RUNS التجريبية، وهي بيانات إضافية لأن StageRecord الأصلي لا يسجل كل تشغيل. عند غياب السجل تظهر علامة —.
- الاستثناءات المسجلة: Finding.exception. السياسة تحدد أثره. الواجهة تقرأ السجل؛ طلب استثناء جديد أو تمديد يحتاج عقد بيانات إضافيًا.
- مؤشرات الإدارة: حسابات العرض، والمشاريع، وسجلات التشغيل التجريبية. حالة GitHub غير متصل.
- رقم PR والبناء وSHA والفرع ونطاق المشروع ميتاداتا تجريبية مرافقة لـ release_id؛ نموذج Evidence الأصلي لا يحفظها.

## أمثلة للتجربة
يبقى المطور ضمن الورك فلو ويظهر في مسار العمل. تسجيل الدخول للداشبورد متاح لأدوار الجودة والأمن والإدارة.
- QA: البناء #132 جاهز للموافقة التجريبية، و#133 يعرض FAIL مع خيار الإرجاع، و#130 بانتظار البيانات.
- السايبر: #128 يعرض FAIL، و#129 يعرض PASS مع نتيجة إعادة التحقق، و#131 يعرض فحصًا مطلوبًا تعطل، و#134 يعرض PASS وصفر ملاحظات، وتصبح حالة القرار «معتمد أمنيًا» بعد موافقة المراجع. الدرع يعرض نتيجة الفحص، وتفتح أزرار الأدلة سجل المراجعة. استخدم زري عينة المشكلة وعينة الاجتياز فوق نتائج البناء لتبديل المثال بسرعة.
- مسؤول الشركة: يراجع حسابات شركته ومؤشرات التشغيل ويعدّل صلاحيات حسابات المعاينة.

## المطلوب عند الربط الفعلي
استبدل RELEASES وRUNS ببيانات CI موثقة تربط معرف التشغيل والإصدار وPR وSHA وتوقيت التنفيذ والأداة وإصدارها. استخدم مخزن Evidence الدائم مع قرارات بشرية مرتبطة بهوية المراجع والتعديل. ربط فحوصات QA وواجهات GitHub والمصادقة الإنتاجية وإدارة الحسابات والتدقيق الإداري أجزاء مستقلة. لا تستخدم كلمة مرور العرض في بيئة مشتركة.

صور الأدوار الأربعة والرئيسية وعن يقظ وعينة التواصل داخل images. اختُبرت الحسابات على المسار نفسه في Edge، وعزل الأدوار والمشاريع، وتصفية الأدوات، وتعطل التشغيل، وربط القرار بالتعديل، وفتح الأدلة، وتبديل اللغة والمظهر.






## التواصل
مسار التواصل يعرض محادثات المشروع التي يكون الحساب مشاركًا فيها. ابدأ بحساب الأمن، وافتح «التواصل» ثم عينة طلب المهلة للبناء 128. أرسل ردًا ثم ادخل بحساب إدارة الشركة للاطلاع عليه. يمكن فتح نقاش من البناء أو تفاصيل ملاحظة، وإضافة موعد حالي وموعد مطلوب. التواريخ التي يكتبها المستخدم بيانات طلب تجريبي، وليست مزامنة مع نظام مواعيد. الموافقة على المهلة تتطلب آلية وصلاحية عمل معتمدة، والواجهة تعرض الطلب بانتظار المراجعة. الرسائل وتغييرات الحسابات والقرارات تحفظ طوال تشغيل الخادم المحلي وتُصفّر عند إعادة تشغيله.

## رحلة العرض الجديدة
الرئيسية تعرض الشعار وتسجيل الدخول وإنشاء حساب، مع رابط «عن يقظ». صفحة /about تشرح دور الوكيل وحلقة إعادة الفحص. /dashboard للمطور والجودة والأمن. /admin لإدارة الشركة ويحتاج جلسة مسؤول الشركة. كلمة المرور التجريبية المشتركة لحسابات العرض هي YaqidhDemo-2026، وهي للتشغيل المحلي فقط. في أي نسخة منشورة اضبط كلمة مرور خاصة بالمتغير YAQIDH_DEMO_PASSWORD (لا تكتبها في أي ملف). وللنشر على عنوان عام اضبط YAQIDH_ALLOWED_HOSTS باسم النطاق (أو أكثر مفصولة بفاصلة)، وإلا يرفض الخادم تسجيل الدخول خارج localhost. الخيار --host يحدد عنوان الاستماع (الحاوية تستخدم 0.0.0.0). التفاصيل في Dockerfile و scripts/start_container.sh.

المطور يبدأ بالبناء 133، ويستطيع تجربة البناء 129 بعد المعالجة. الجودة تستخدم 133 و132. الأمن يستخدم 128 لوجود مانع، و134 لتجربة الموافقة بعد الاجتياز، و135 لعرض بناء معتمد أمنيًا مسبقًا. لا يوجد سجل زمني كامل، لذا تعرض لوحة المراجعة حالة غياب البيانات للاتجاه الزمني.

من /signup، استخدم رمز الدعوة التجريبي YAQIDH-DEMO وأدخل اسمًا لاتينيًا مميزًا وكلمة مرور من عشرة أحرف فأكثر. الطلب يبقى معلقًا حتى يفعّله مسؤول الشركة. يوجد طلب demo-reviewer معد مسبقًا. كلمات المرور للحسابات الجديدة تُشتق منها بصمة مملّحة في الخادم. نموذج الدعوة والتخزين والجلسات للمعاينة المحلية. الطلبات والحسابات الجديدة لا تدوم بعد إيقاف الخادم.

لوحة الشركة تعرض دونت لحالات تشغيل الأدوات وخطًا يوميًا لسجلات تشغيل تجريبية مؤرخة، حسب فلاتر المشروع والمرحلة. مؤشر واجهة البيانات يصف استجابة طلب لوحة الإدارة الحالي. هوية مرسل كل رسالة ودوره يستمدهما الخادم من الجلسة. يوجّه الخادم نقاش المطور إلى المراجعين المسندين للمرحلة، ونقاش المراجع إلى المطور صاحب البناء. يستطيع مسؤول الشركة مراسلة المطور من سجل التشغيلات في نطاق مشروعه.

يعرض خط المطور نتائج أبنيته المسندة من تواريخ المعاينة. في «التواصل» توجد عينة إرجاع من الجودة للبناء 133.

الديمو التفاعلي: عند تشغيل الخادم مع YAQIDH_DEMO_MODE=1 (وهو الافتراضي في الحاوية) يظهر زر «جرّب الديمو» في الصفحة الرئيسية، ويلعب الزائر أدوار المطوّر والجودة والأمن على طلب نتائج أدواته مسجّلة من تشغيل حقيقي (scripts/record_demo_fixtures.py ثم demo_replay/fixtures.json) وتُرسل لواجهة يقظ الحقيقية.
